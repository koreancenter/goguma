# 🍠 GOGUMA IMPLEMENTATION ROADMAP (roadmap.md)

> **문서 목적**: 비개발 도메인 전문가가 본인의 실무 경험을 체계적인 UI/UX와 동작하는 소프트웨어로 전환하기 위한 체크리스트 기반 실행 로드맵
> **총 예상 소요 시간**: 약 6시간 ~ 8시간 (기획 2시간 + 프로토타입 검증 1.5시간 + 에이전트 빌드/배포 3~4시간)
> **핵심 원칙**: 무리하게 코딩을 직접 배우려 하지 말고, 각 단계의 체크박스를 순서대로 채우며 AI 에이전트에게 명확한 경계선을 전달한다.

## Phase 1: [씨앗] 도메인 업무 프로세스 활자화

> **목표 시간**: 60분 ~ 90분
> **핵심**: 개발 용어를 배제하고 평소 현장(병원, 매장, 사무실)에서 처리하던 일의 순서를 문장으로 옮긴다.

* [ ] **1.1. 단일 사용자 페르소나 정의 (15분)**
* [ ] 이 앱을 매일 가장 오래 사용할 단 한 사람 지정 (예: 상담 실장, 매장 점주, 예약 고객)
* [ ] 해당 사용자가 앱을 켜는 상황(모바일 접속 vs 데스크톱 업무 중) 확정


* [ ] **1.2. 이상적인 업무 흐름(Happy Path) 3단계 기록 (30분)**
* [ ] 시작: 사용자가 앱에 들어와서 처음 입력/선택하는 행동 정의
* [ ] 중간: 입력된 내용을 관리자가 확인하거나 승인하는 처리 단계 정의
* [ ] 완료: 최종 결과(알림, 장부 저장, 영수증 표시 등)가 나타나는 형태 정의


* [ ] **1.3. 엑셀 열(Column) 데이터 나열 (30분)**
* [ ] 평소 장부나 메모장에 적던 필수 항목 5~8개 적기 (예: 고객명, 연락처, 예약일시, 특이사항)
* [ ] 꼭 채워야 하는 필수 항목(Required)과 안 써도 되는 선택 항목(Optional) 구분


* [ ] **1.4. 산출물 동기화 확인 (15분)**
* [ ] `01_proposal.md`에 비즈니스 배경과 핵심 가치가 반영되었는지 확인
* [ ] `06_DATA_SCHEMA.md`에 데이터 항목들이 엔티티 형태로 추출되었는지 확인

## Phase 2: [줄기] 도메인 지식의 UI/UX 시각화

> **목표 시간**: 45분 ~ 60분
> **핵심**: 정리된 업무 흐름을 복잡한 대시보드가 아닌, 눈이 편안한 단정한 화면 구조로 배치한다.

* [ ] **2.1. 사이트맵 및 화면 분할 최소화 (15분)**
* [ ] 전체 화면을 2개 이내로 제한 (화면 1: 고객용 접수/신청 뷰, 화면 2: 관리자 확인 장부 뷰)
* [ ] 불필요한 서브 메뉴 및 뎁스(Depth) 제거


* [ ] **2.2. 페이퍼 스타일 UI 요소 매핑 (20분)**
* [ ] 텍스트 입력부: 답답한 사각 박스 대신 가독성 높은 밑줄형(Underline) 필드로 지정
* [ ] 주요 액션: 한 화면에 고구마 껍질색 메인 CTA 버튼 1개만 강조 배치
* [ ] 정보 영역: 카드 중첩(Box-in-box) 없이 넉넉한 여백과 얇은 구분선으로만 구획 정리

* [ ] **2.3. 단일 파일 프로토타입(`prototype.html`) 초안 렌더링 (15분)**
* [ ] 고구마 앱 우측 미리보기 패널에서 생성된 인터페이스 즉시 확인
* [ ] 모바일 뷰와 데스크톱 와이드 뷰에서 레이아웃 깨짐이 없는지 점검

## Phase 3: [뿌리] 가짜 데이터 및 인터랙션 검증

> **목표 시간**: 45분 ~ 60분
> **핵심**: 실제 서버나 코드를 짜기 전에, 브라우저 상에서 마우스로 누르고 입력하며 '업무 손맛'을 확인한다.

* [ ] **3.1. 현실적인 도메인 목데이터(Mock Data) 3건 입력 (15분)**
* [ ] 실제 현장에서 마주치는 현실적인 이름, 날짜, 문구를 프로토타입 폼에 직접 타이핑
* [ ] 글자가 길어질 때 줄바꿈이 자연스러운지 확인

* [ ] **3.2. 핵심 동작(CRUD 목업) 테스트 (15분)**
* [ ] [등록/신청] 클릭 시 하단 목록에 새로운 행이 즉시 추가되는지 확인
* [ ] [삭제/완료] 클릭 시 목록에서 정상적으로 제거되는지 확인

* [ ] **3.3. 도메인 전문가 관점의 예외(Edge Case) 규칙 도출 (20분)**
* [ ] 빈 값을 넣고 버튼을 눌렀을 때의 경고 처리 명시
* [ ] 겹치는 시간대나 잘못된 번호 입력 시의 방어 규칙을 `08_TEST_CHECKLIST.md`에 추가

* [ ] **3.4. 화면 흐름 최종 승인 (10분)**
* [ ] "이 프로토타입 그대로 코드가 완성되면 내 업무에 바로 쓸 수 있는가?" 자문 후 확정

## Phase 4: [수확] AI 코딩 에이전트 주입 및 검증 배포

> **목표 시간**: 120분 ~ 180분
> **핵심**: 검증된 청사진 묶음을 Cursor, Claude Code 등에 주입하여 토큰 낭비 없이 1회에 정상 코드를 완성한다.

* [ ] **4.1. 청사진 아티팩트 번들 패키징 (10분)**
* [ ] 고구마 앱에서 `goguma-blueprint-[project].zip` 일괄 다운로드
* [ ] 압축 파일 내 `prototype.html`, `.cursorrules`, `docs/` 11종 문서 무결성 확인

* [ ] **4.2. 에이전트 작업 공간 초기화 (20분)**
* [ ] 새 폴더 생성 후 다운로드받은 번들 압축 해제
* [ ] Cursor, Claude Code, Cline 등 작업할 에이전트 환경 실행

* [ ] **4.3. 1차 골든 프롬프트(Golden Prompt) 주입 (30분)**
* [ ] 에이전트에게 `docs/` 전체와 `prototype.html`을 컨텍스트로 지정
* [ ] 지시문 실행: *"prototype.html의 UI/인터랙션을 100% 유지하며 05_ARCH_CONSTITUTION.md 규칙에 맞춰 프로덕션 코드를 스캐폴딩하라."*

* [ ] **4.4. 도메인 전문가 직접 검수 (40분)**
* [ ] 에이전트가 완성한 로컬 서버(`localhost`) 실행
* [ ] `08_TEST_CHECKLIST.md`를 열고 마우스로 하나씩 눌러보며 체크박스 검수 진행

* [ ] **4.5. 서버리스 배포 (30분)**
* [ ] Cloudflare Pages 또는 Vercel을 연동하여 정적 빌드 배포
* [ ] 본인 스마트폰으로 실제 URL에 접속해 모바일 사용성 최종 확인
