# 📋 GOGUMA DOMAIN TEST CHECKLIST (08_TEST_CHECKLIST.md)

> **문서 목적**: 비전문 개발자(도메인 전문가)가 AI 에이전트의 완성 코드를 인수받았을 때, 코드 검토 없이 화면을 직접 조작하며 정상 동작 여부를 판정하는 사용자 인수 테스트(UAT) 체크리스트
> **검수 원칙**: "코드는 보지 않는다. 오직 사용자의 눈과 손으로 클릭하고 입력하며 상식대로 돌아가는지만 확인한다."

---

## 🧭 검수 진행 방법 (How to Test)

1. 브라우저에서 완성된 앱 화면(`localhost` 또는 배포 URL)을 띄웁니다.
2. 아래 4개 구역의 체크박스를 위에서부터 순서대로 직접 클릭하고 타이핑하며 테스트합니다.
3. 하나라도 실패(`[ ]`)하면 해당 항목의 문구를 그대로 복사해 AI 에이전트에게 전달합니다:
> *"이 체크리스트 항목이 실패했습니다: [실패한 항목 문구]. 05_ARCH_CONSTITUTION.md 규칙을 지키면서 이 동작이 정상 작동하도록 수정하세요."*

---

## 1. 첫인상 및 화면(UI) 기본 점검 (Visual Sanity)

* [ ] **1.1. 첫 화면 로딩 및 눈부심 점검**
* [ ] 화면을 켰을 때 깜빡임이나 흰색 빈 화면 없이 1초 안에 메인 화면이 뜨는가?
* [ ] 웜 도화지(아이보리) 톤이 잘 유지되어 장시간 보아도 눈이 피로하지 않은가?


* [ ] **1.2. 폰트 및 텍스트 뭉개짐 확인**
* [ ] 큰 제목과 본문 글꼴이 정갈한 책처럼 또렷하게 읽히며 글자가 겹치는 곳이 없는가?
* [ ] `benchmark_url_desc` 같은 영문 시스템 변수나 번역 키가 화면에 날것으로 노출되지 않는가?


* [ ] **1.3. 와이드 모니터 및 모바일 반응형 점검**
* [ ] 브라우저 창을 좌우로 넓혔을 때 내용이 과도하게 찢어지거나 한쪽으로 쏠리지 않는가?
* [ ] 스마트폰(또는 개발자 도구 모바일 모드)으로 보았을 때 가로 스크롤 없이 모든 버튼이 손가락으로 누르기 편한 크기인가?

---

## 2. 장부 데이터 입력 및 목록 동작 (Data CRUD Test)

> **도메인 핵심**: "내가 엑셀에 한 줄 적고 지우던 일이 웹 화면에서도 그대로 되는가?"

* [ ] **2.1. 정상 데이터 1건 등록 (Happy Path)**
* [ ] 실제 손님/환자/업무 데이터를 입력창에 채우고 [등록/신청] 버튼을 누른다.
* [ ] 화면 하단이나 목록 영역에 방금 입력한 내용이 즉시 한 줄 추가되는가?
* [ ] 등록 버튼을 누른 뒤 입력창이 깨끗하게 비워져 다음 입력을 받을 준비가 되는가?


* [ ] **2.2. 연속 3건 등록 및 목록 순서 확인**
* [ ] 서로 다른 내용으로 3건을 연달아 등록했을 때 목록에 3개가 순서대로 정렬되는가?
* [ ] 긴 문장(메모나 요청사항에 50자 이상)을 적어도 카드 밖으로 글자가 삐져나가지 않고 자연스럽게 줄바꿈되는가?


* [ ] **2.3. 새로고침 후 데이터 유지 확인 (Local Persistence)**
* [ ] 3건이 등록된 상태에서 브라우저 [새로고침(F5)]을 누른다.
* [ ] 방금 등록한 3건의 데이터가 사라지지 않고 그대로 화면에 남아 있는가?


* [ ] **2.4. 항목 상태 변경 및 삭제 확인**
* [ ] [완료] 또는 [승인] 버튼을 눌렀을 때 상태 표시(칩/라벨)의 색상이나 텍스트가 즉각 바뀌는가?
* [ ] [삭제] 버튼을 눌렀을 때 해당 항목이 목록에서 깔끔하게 사라지는가?

## 3. 실수 및 예외 상황 방어 점검 (Edge Case Defense)

> **도메인 핵심**: "손님이 실수로 잘못 누르거나 이상한 값을 넣었을 때 앱이 망가지지 않는가?"

* [ ] **3.1. 빈칸 입력 방어 (Empty Input)**
* [ ] 입력창에 아무것도 쓰지 않고 [등록] 버튼을 누른다.
* [ ] 빈 데이터가 덜컥 등록되지 않고, "필수 항목을 입력해 주세요" 같은 친절한 안내가 뜨는가?


* [ ] **3.2. 형식 오류 방어 (Format Validation)**
* [ ] 전화번호 입력란에 글자를 적거나, 날짜에 엉뚱한 값을 넣고 시도한다.
* [ ] 올바른 양식으로 입력하라는 안내 문구가 적절히 표시되는가?


* [ ] **3.3. 버튼 연타 방어 (Double Submit)**
* [ ] [등록] 버튼을 1초에 서너 번 연속으로 빠르게 광클해 본다.
* [ ] 같은 데이터가 중복으로 3~4개씩 복제되어 등록되지 않는가?

---

## 4. 안전 및 독립성 점검 (Security & Offline Test)

* [ ] **4.1. 인터넷 연결 해제(오프라인) 상태 테스트**
* [ ] Wi-Fi를 끄거나 비행기 탑승 모드로 전환한다.
* [ ] 기존에 저장해 둔 목록이 여전히 잘 보이고, 새로운 메모 등록이 로컬에서 정상 작동하는가?


* [ ] **4.2. 외부 데이터 유출 차단 확인**
* [ ] 브라우저 네트워크 탭을 확인했을 때, 내가 입력한 환자/고객 정보가 모르는 외부 서버 주소로 전송되지 않는가?

---

## 5. 최종 판정 (Sign-off)

* 모든 항목이 체크(`[x]`)되었을 때 비로소 "이 소프트웨어는 내 실무에 투입할 수 있는 완성본"으로 승인하고 배포를 진행합니다.
